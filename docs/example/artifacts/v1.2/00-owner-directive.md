## What was said

Two binding directives, after reviewing v1.1 in a browser:

1. **Plain language.** The copy is written for design and engineering insiders — *intake,
   fidelity, wireframe, token system, hard floor.* Rewrite **all** body copy, EN and VI,
   so a smart reader with no technical or design background follows it. Explain by
   everyday analogy rather than vocabulary. The mono stamps (file names, step codes, FIG
   labels) may stay as visual decoration; the sentences a human reads must be plain.
2. **Motion as a feature of the page.** The owner wants an immediate "wow" on first view.
   The marketing delight budget is now **owner-mandated wide**. Motion must live in every
   section, not only in the four demonstration rigs.

## What that overrides

| Pipeline preference | Owner's call | Status |
| --- | --- | --- |
| Motion playbook frequency tiers keep entrance choreography rare, and the v2 spec deliberately kept the refusal list longer than the accepted list | Wide delight budget; motion is a feature of every section | **Overridden.** 21 accepted / 18 refused — the accepted list is now longer for the first time |
| Copy register was set by the direction gate as "engineering specimen sheet", which invited specialist vocabulary | Plain language, everyday analogy | **Overridden.** The *visual* specimen language stays; the prose register does not |

**The pipeline's restraint preference did not lose an argument — it was outranked.**
That distinction matters for the next run: the default stays restrained. This page is
a marketing surface whose owner asked for the budget to be spent, and the spend is
recorded per-element in `06-motion-spec.md` with the same four questions applied to
each one. Nothing was waved through.

## What did not move

Rule Zero, the hard floor, reduced-motion compliance, transform/opacity-only, and
"data the user reads doesn't jitter" were all named as unchanged in the directive and
are all measured in `07-uat-report.md`. The wide budget bought more motion, not
cheaper motion.
