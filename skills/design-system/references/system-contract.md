# System contract: the design-system package

## Contents

Find a section: `grep -n "^## " system-contract.md`
- Package tree — building or changing the folder layout
- Required, conditional, optional — checking what one entry must hold
- Read order — deciding which file an agent opens first
- Section budget — adding Markdown files outside components
- Canonical map — writing canonical-map.json
- Agent adapters live in the parent folder — wiring AGENTS.md, CLAUDE.md, GEMINI.md
- Refused and generated paths — a path is refused or generated
- Code index — looking up an error code

One folder, `design-system/`, serves two readers: Claude Design (package format `v:3`, read on 2026-10-22, research preview) and any coding agent. This file is the folder tree and the rules around it. Token grammar: `token-contract.md`. `DESIGN.md` shape: `design-md-spec.md`. Why this shape: ADR 0001 and ADR 0002 under `docs/architecture/adr/`.

Errors print as `<code>: <path>[: detail]` on stderr; warnings print as `WARN <code>: <path>[: detail]` on stdout; paths are relative to the package root with `/` separators. Size caps and how they are measured: section "Size caps" below. Every code, with its level and path, is listed once more in "Code index" at the end.

## Package tree

```
design-system/                          ← = project/ of a Claude Design system; NO SKILL.md/AGENTS.md/CLAUDE.md/package.json/dot-*
├─ DESIGN.md              MUST   reading root for every agent: YAML front matter (generated from tokens.json) + 8 ## sections per Google alpha;
│                                 Overview carries the package contract (read order · owner/version/status · canonical by domain)
├─ README.md              MUST   brand book for Claude Design (3 headings in profile full) — does not repeat DESIGN.md
├─ tokens.json            MUST   THE DATA ROOT for tokens, v3 list {name,value,usage}
├─ design-system.json     MUST   v3 index, written last
├─ canonical-map.json     MUST   schemaVersion 1; profile; canonical; components.<C>.source; checks.contrast; decisions
├─ viewer.html            MUST   self-contained viewer page, GENERATED by build-design-system.py, ≤512 KB (platform cap), target ≤300 KB
├─ provenance.md          OPTIONAL  source log observed/inferred/unknown (becomes a brand-book section)
├─ CHANGELOG.md           OPTIONAL  append only
├─ components/
│  ├─ Cover/preview.html  MUST   line 1 marker @dsCard; 1 inline SVG + 2 text elements (per the Claude Design cover reference)
│  ├─ <Comp>/README.md    MUST-if   first sentence = summary
│  ├─ <Comp>/preview.html MUST-if   marker on line 1; no iframe/object/embed; CDN pinned to a version
│  └─ <Template>/preview.html OPTIONAL  marker page + group="Templates"
├─ assets/<Group>/README.md  MUST-if   lists every file, its source and usage right; never invent a logo
├─ assets/<Group>/<file>  OPTIONAL  ≤12 MB stored; the viewer inlines only files ≤64 KB
├─ fonts/<file>           OPTIONAL  woff2/woff/ttf/otf ≤1 MB stored, with usage right, listed in type.fonts[].file
├─ patterns/<Pattern>.md  OPTIONAL  a brand-book section
├─ surfaces/<s>/{rules.md, screens/<route>.md}  OPTIONAL  brand-book sections
└─ (NEVER hand-written: tokens.css, manifest.json, api/**, migration-map.json, publish-progress.json, archived/**)
```

The package root is `project/` of a Claude Design system. Harness wrapper files live one level up (see "Agent adapters live in the parent folder"). Only create the branches that have a real object behind them; never add empty folders.

## Required, conditional, optional

The tree marks each entry. `MUST` means the verifier reports an error when it is missing or wrong (exit 1). `MUST-if` is the conditional form: an error only when the object exists (a component folder, an asset group). `OPTIONAL` means the content is never checked; the verifier still checks the name, the section budget and the size caps, and for a font file the four-byte signature.

### Required files

| Entry | What is checked | Codes |
|---|---|---|
| `design-system.json` | version 3, `layout` is `"files"`, non-empty `title`, `namespace` is an ASCII JavaScript identifier; `createdOnFiles` should be present and, when present, has `v` = 1 and an ISO-8601 `at` | `missing_required_file`, `unsupported_format_version`, `missing_index_key`, `invalid_index_value`; warning `index_marker_missing` |
| `README.md` | exists, at most 200 000 bytes, no level-1 heading that repeats `title`, no "Provenance" or "Next steps" section; profile `full` needs the three headings "Content fundamentals", "Visual foundations", "Iconography" | `readme_missing_section`, `readme_too_large`, `readme_forbidden_section`; warning `readme_unknown_token` |
| `tokens.json` | grammar in `token-contract.md` | `token-contract.md`, section "Error codes" |
| `DESIGN.md` | front matter regenerated and checked for string equality, eight sections in order, references resolve | `design-md-spec.md`, section "What the verifier checks" |
| `canonical-map.json` | schema in "Canonical map" below | `invalid_manifest`, `invalid_canonical`, `invalid_external`, `invalid_status`, `invalid_id`, `invalid_path`, `missing_path` (names kept from the earlier manifest check) |
| `viewer.html` | exists, equals the regenerated page, at most 512 000 bytes (target 300 000), no outside resources, no event-handler attributes, a content-security meta that pins the one script by hash | `viewer_missing`, `viewer_stale`, `viewer_too_large`, `viewer_external_ref`, `viewer_forbidden_tag`, `viewer_inline_handler`, `viewer_forbidden_api`, `viewer_missing_csp`, `viewer_csp_weak`, `viewer_a11y`, `viewer_coverage`, `viewer_leak`; warning `viewer_large` |
| `components/Cover/preview.html` | line 1 is the `@dsCard` marker, at most 256 000 bytes, one inline `<svg>`, no embedding tags, CDN URLs pinned to an exact version | `cover_missing`, `card_marker_missing`, `preview_too_large`, `forbidden_tag`, `unpinned_cdn`, `cover_shape` |

### Conditional entries

- `components/<Comp>/README.md` and `components/<Comp>/preview.html`: profile `full` requires both for every component folder except `Cover` and folders whose preview carries the `page` marker, plus a `components.<Comp>.source` entry in `canonical-map.json`. The folder name must be an ASCII JavaScript identifier. The first sentence of the README is the summary. A README over 64 000 bytes gives `WARN component_readme_large`. Codes: `component_name_invalid`, `component_incomplete`, `component_without_source`.
- A preview may not use `iframe`, `frame`, `object`, `embed`, `portal` or `noscript` (`forbidden_tag`), may not exceed 256 000 bytes (`preview_too_large`), and every CDN URL pins an exact version (`unpinned_cdn`). A marker `height` outside 40 to 4000 gives `WARN card_marker_height`.
- `assets/<Group>/README.md`: every direct subfolder of `assets/` has one; it names each file in the group, its source and its usage right, and says which ink a one-colour SVG uses. Never invent a logo: with no real logo, use a text wordmark and say why in this README. Codes: `asset_group_readme_missing`, `asset_unlisted`. A single asset whose stored size is over 12 000 000 bytes (an SVG over 2 000 000 raw bytes) is an error: `asset_too_large`.
- `fonts/<file>`: listed in `type.fonts[].file`, woff2, woff, ttf or otf by its first four bytes, stored size at most 1 000 000 bytes, with usage right. Codes: `font_file_missing`, `font_file_invalid`, `font_file_too_large`.

### Optional entries

`provenance.md`, `CHANGELOG.md` (append only), `patterns/<Pattern>.md`, `surfaces/<s>/rules.md`, `surfaces/<s>/screens/<route>.md`, `components/<Template>/preview.html` (marker `page` with `group="Templates"`). Names, the section budget and the size caps are checked; content is not.

Advisory checklist for a pattern, template or screen file (not machine-checked): the user task; information order and hierarchy; grid, widths and breakpoints; data formats; loading, empty, error and permission states; interaction and recovery; keyboard, focus and accessibility; links to the components and patterns used. Unknown fields say `unknown` and how to find out; fields that do not apply say `N/A` with a reason.

### Size caps

All caps are decimal: 64 KB = 64 000 bytes, 256 KB = 256 000, 512 KB = 512 000, 1 MB = 1 000 000, 2 MB = 2 000 000, 12 MB = 12 000 000, 14 MB = 14 000 000. The platform counts the stored form of a file: the text itself for a text file, a base64 string (4 bytes for every 3) for a binary file. In the `files` layout this contract requires, the format notes list no further page cap for kept files, so the numbers here are the contract's own caps and the verifier applies them as follows:

- Text files (`.md`, `.mdx`, `.json`, `.html`, `.css`, `.svg`, `.txt`, `.js`, `.ts`, `.yml`, `.yaml`, `.csv`): the cap is checked on the raw bytes of the file. The escaping the page adds when it stores text is not modelled.
- Binary files (every file under `fonts/`, and every asset that is not a text file): the cap is checked on the stored-size estimate `stored = 4 * ceil(raw / 3)`. A font therefore passes up to 750 000 raw bytes and an asset up to 9 000 000. The error detail prints both numbers: `<raw> raw, <stored> stored > <cap>`.
- Package total: the sum of the stored sizes of every file in the package (text raw, binary estimate) above 14 000 000 gives `WARN package_total_large: <n> > 14000000`. A warning, not an error, because in the `files` layout the page keeps the files outside its own table.
- `kept_file_large` is measured on the raw bytes of every file it covers, binary files outside `fonts/` and `assets/` included; no stored-size estimate applies to it.
- `design-system.json` and `canonical-map.json` are read in full up to 512 000 bytes. A larger file cannot be checked, so it is an error (`invalid_index_value` or `invalid_manifest`, detail `size: <n> > 512000`) and never also a `kept_file_large` warning.
- `DESIGN.md` is scanned up to 512 000 bytes; a heading that starts after that point counts as missing.

| Cap | Applies to | Code |
|---|---|---|
| 200 000 | `README.md` | `readme_too_large` |
| 512 000 | `tokens.json`; `viewer.html` (target 300 000); any other file kept without UI | `limit_exceeded`; `viewer_too_large`, warning `viewer_large`; warning `kept_file_large` |
| 512 000 | `design-system.json`, `canonical-map.json` | `invalid_index_value`, `invalid_manifest` (detail `size: <n> > 512000`) |
| 256 000 | every `preview.html` | `preview_too_large` |
| 64 000 | `components/<Comp>/README.md` | warning `component_readme_large` |
| 1 000 000 stored | `fonts/<file>` | `font_file_too_large` |
| 12 000 000 stored; SVG 2 000 000 raw | `assets/<Group>/<file>` | `asset_too_large` |
| 14 000 000 stored | the whole package | warning `package_total_large` |

### Profiles

| Profile | How selected | Rules |
|---|---|---|
| `full` | default, or `profile: "full"` | everything above |
| `minimal` | `--profile minimal` or `profile: "minimal"` in `canonical-map.json` | 6 to 10 colours in exactly one theme; 5 to 7 text styles; exactly 4 spacing tokens; exactly 3 radius tokens; README is one paragraph of at least 80 characters (the three headings are not required); no component other than `Cover`. Code: `minimal_profile_violation` |

### Contrast

Text and surface pairs are declared in `canonical-map.json` under `checks.contrast`, not in `tokens.json`. Each pair is measured in every theme against its `min` (default 4.5; 3.0 for large text, borders, focus rings and icons). No declared pair gives `WARN contrast_unchecked` and the PASS line says so; a colour that cannot be converted to sRGB gives `WARN contrast_unsupported_space`; a failing pair is `contrast_below_min`.

### Cover folder is bare

`components/Cover/` holds `preview.html` and nothing else. Any sibling (`README.md`, `Cover.d.ts`, `index.html`), or a `@ds-bundle` header in `components/bundle.js` that lists `Cover`, turns the cover into an ordinary component and the system loses its cover. The verifier reports `cover_not_bare: components/Cover/<file>`; for the bundle case the path is `components/bundle.js` with the detail `bundle header lists Cover`.

Cover rule: line 1 is `<!-- @dsCard height=N -->` with N from 240 to 360 (outside it: `WARN card_marker_height`); the frame is a fixed 960 by N; exactly one inline `<svg>` (any other count: `cover_shape: components/Cover/preview.html: <n> svg`) plus two text elements, the name and a one-line tagline (not machine-checked); no gradient, shadow or motion; every `fill`, `stroke` and `rx` goes through a class bound to a token.

### Viewer rules

`viewer.html` is a static page the build writes; the verifier regenerates it and matches the result, with CRLF and lone CR read as LF on both sides. These are the rules of the generator, so that a reader knows why the page looks as it does.

- The cover SVG and any SVG asset pass an allow-list: drawing elements, text, gradients, clip and mask, simple filters. No `script`, `style`, `title`, `image`, `a`, `animate` or `foreignObject`, no comment or CDATA section, and `href` or `url()` may point only at an `#id` of the same file. Cover ids get the prefix `cover-` so that they cannot clash with ids of the page. An SVG that fails the list is shown by name only and the build prints `WARN viewer_asset_skipped: <path>`.
- An image is embedded when it is at most 65 536 bytes, and all embedded images together stay under 250 000 characters of data URI. Anything beyond is listed by name with the same warning.
- The root `README.md` is not shown. A component README is cut at 64 000 bytes. In shown text `=` and `//` are written as numeric entities. A Markdown link survives only when it points at a relative file inside the package, after percent-decoding; any other link keeps its text and loses its target. The page makes no network call.
- `data-token`, `data-component` and `data-asset` count the objects of the package: tokens; every folder under `components/` except `Cover`, `lib` and `src`; every file under `assets/` except `assets/<Group>/README.md`. The verifier counts the same way (`viewer_coverage`).
- The stale and coverage checks run only when `design-system.json` and `tokens.json` are valid. A page over 512 000 bytes is reported as `viewer_too_large` and nothing else about it.
- The content-security meta is `default-src 'none'; img-src data:; style-src 'unsafe-inline'; script-src 'sha256-<digest>'; script-src-attr 'none'; base-uri 'none'; form-action 'none'`. The page has one script, and `<digest>` is the base64 SHA-256 of its text with LF line endings (a browser reads CRLF in a page as LF), worked out when the page is written. A script of any other text does not run, an event-handler attribute does not run (`script-src-attr`), and an injected `<base>` or form cannot redirect the page (`base-uri` and `form-action` do not fall back to `default-src`). `style-src 'unsafe-inline'` stays because the cover SVG and the page use style attributes; with `default-src 'none'` and `img-src data:` nothing can be fetched. A policy in a `<meta>` cannot carry `frame-ancestors`, `sandbox` or `report-uri`, so none is written, and the page cannot forbid being framed.
- The verifier reads the policy as a browser does: directive names and keywords have no case, the first of a repeated directive counts, entities are undone. It requires exactly the directives above, `script-src` holding the one hash and nothing else, and it works the hash out again from the script of the page (the digest itself is exact, byte for byte). A fault is `viewer_csp_weak` with the directive named; a page without a meta whose policy holds `default-src 'none'` is `viewer_missing_csp`. A stricter policy will change this line, the generator and the verifier together.
- The Files screen says that sizes of text files are measured with LF line endings: a file with a suffix in `.md .mdx .json .html .css .svg .txt .js .ts .yml .yaml .csv` is shown with the size it has after CRLF and lone CR become LF, an embedded SVG is encoded after the same change, and a README cut falls at the same place. A package copied through a CRLF checkout therefore builds the same page and is not `viewer_stale` or `design_md_stale`. Fonts, images and other files keep their stored size. At most 12 000 000 bytes of one file, 64 000 000 bytes in all and 2 000 files are read for this; a file beyond a limit is shown with its stored size.
- The page lists the files of the package but not itself, and its own comments are neutral.

### Recognised, never generated

The verifier recognises, and the PASS line then adds `bundle`, when it finds `components/bundle.js`, `components/bundle.css`, `components/index.d.ts`, `components/<Comp>/<Comp>.d.ts`, `components/lib/**` or `components/src/**`. This skill never writes them; Claude Design owns their limits.

### Legacy folders

`ui-kit/`, `specimens/`, `integrations/` and, from the earlier layout of this skill, `brand/` and `foundations/` give `WARN legacy_layout_dir: <folder>`. Markdown inside them would silently become brand-book sections, so move the content before importing.

## Read order

`DESIGN.md` Overview states both branches; every package repeats them there.

- Claude Design: `README.md` → `tokens.json` → `components/*/README.md`.
- Any other agent: `DESIGN.md` → `tokens.json` → `canonical-map.json` → `components/`.

Two roots, two roles. The reading root is `README.md` for Claude Design and `DESIGN.md` for everything else. The data root is always `tokens.json`; the `DESIGN.md` front matter and any DTCG file are derived from it and never edited by hand. The `DESIGN.md` Overview also gives owner, version, status and the canonical file for each domain (brand, tokens, components). `DESIGN.md` does not repeat the brand book, and the body names tokens without copying values.

## Section budget

Claude Design turns every Markdown file outside `components/` and `archived/` into a brand-book section, in path order, at most 24. The verifier counts statically: every `*.md` and `*.mdx` in the package except the root `README.md` and anything under `components/` or `archived/`. That includes `DESIGN.md`, `provenance.md`, `CHANGELOG.md`, `patterns/**`, `surfaces/**` and `assets/<Group>/README.md`. More than 24 gives `WARN sections_over_limit: <n> > 24: <paths in path order>`; it is a warning because the files stay in the package.

Keep the profile `full` fixture at 10 or fewer. For `surfaces/`, use one `rules.md` per surface and put approved screens into few files (`screens/<route>.md` only for screens that are signed off). Other size warnings: `file_count_high` above 1 000 files, `kept_file_large` for any file kept without UI over 512 000 bytes, `package_total_large` for a package whose stored size passes 14 000 000 bytes (see "Size caps").

## Canonical map

`canonical-map.json` replaces the earlier `manifest.json`; that name is generated by the Claude Design page, so a hand-written file with it is refused as `generated_file_present`.

```json
{
  "schemaVersion": "1",
  "system": {"id": "sample-studio", "version": "0.1.0", "status": "draft"},
  "profile": "minimal",
  "canonical": {
    "brand": {"kind": "file", "path": "README.md"},
    "tokens": {"kind": "file", "path": "tokens.json"},
    "components": {"kind": "external", "url": "https://example.com/storybook"}
  },
  "components": {"Button": {"source": "src/Button.tsx"}},
  "checks": {"contrast": [{"fg": "text", "bg": "bg", "min": 4.5, "large": false}]},
  "decisions": []
}
```

- `status` is one of `draft`, `pending`, `as-is`, `proposed`, `approved`, `deprecated`.
- `canonical.<domain>` is `{"kind": "file", "path"}` (relative to the package root), `{"kind": "repo-path", "path"}` (relative to the parent folder of the package, the project root) or `{"kind": "external", "url"}` (an `https` pointer with no credentials; never fetched, so it proves nothing about availability or rights). A local source has no `url`; an external one has no `path`. One domain has one canonical source.
- `components.<Comp>.source` is a path or an external URL under the same rules.
- `checks.contrast[]` entries name token names for `fg` and `bg`.
- `decisions[]` records owner decisions as data (pending or quoted). A partial map is allowed for a draft; do not invent paths.
- Every path goes through the safe-path check before any read: no absolute path, no `..`, no backslash or drive letter, no sensitive name, no link.

Authority: brand guidance confirmed by the owner describes the target; code at the baseline describes the present. A README, an export or an image never wins by default. Record drift as domain → source A → source B → impact → proposal → owner decision.

## Agent adapters live in the parent folder

Harness wrappers belong to the project that uses the package, not to the package. They sit next to `design-system/`:

- `AGENTS.md`: the real instructions, pointing at `design-system/DESIGN.md`.
- `CLAUDE.md`: the single line `@AGENTS.md`.
- `GEMINI.md`: a short prose pointer.

Each is at most 30 lines. `build-design-system.py --package <root>/design-system --adapters <root>` writes them from the `.tmpl` templates of this skill and never overwrites: an existing file prints `WARN adapter_exists: <name>` and a proposal block. The templates carry a `.tmpl` suffix so that a harness does not load them as rules while they sit inside the plugin.

## Refused and generated paths

Claude Design refuses these inside a package; the verifier reports `refused_path: <path>` before opening anything:

- `SKILL.md`, `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` at any depth.
- `package.json`, `tsconfig.json`, `deno.json`, `bunfig.toml`, and a `node_modules` folder, at any depth.
- Lockfiles: `package-lock.json`, `npm-shrinkwrap.json`, `yarn.lock`, `pnpm-lock.yaml`, `bun.lock`, `bun.lockb`, `deno.lock`.
- Any path segment that starts with a dot, except exactly `.image-slots.state.json`.
- 8.3 short names: a segment matching `~` followed by a digit, such as `NAME~1`.
- `index.html` at the package root and `components/<Comp>/index.html` (an alias of `preview.html`). An `index.html` anywhere else gives `WARN index_html_nested`, because the refusal depth is not confirmed.
- `design-system.json` anywhere except the root (at the root it is the required index).
- An `artifact-type/` folder.

Files the page generates itself are `generated_file_present: <path>`: `manifest.json`, `tokens.css`, `api/**`, `migration-map.json`, `publish-progress.json`, `archived/**`. Do not write them by hand.

Sensitive or escaping paths (`.env*`, `*.pem`, `credentials`, a path leaving the package, a link) are refused with `refused_sensitive_path` and never opened. The refused-path check runs right after that one and before any read.

A link or junction at `viewer.html` or `DESIGN.md` is `refused_sensitive_path`; a folder with either name makes the build print `input_error: PermissionError`. The build writes in place, not atomically, and follows hard links, so run it on a package you own.
